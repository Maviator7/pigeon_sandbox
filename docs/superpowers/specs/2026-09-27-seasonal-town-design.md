# 四季のある鳩の街 — 設計

## 目的

ひとつの街を長く眺め、育て続ける理由を増やす。ゲーム内時間で春夏秋冬が巡り、街の色、鳩の行き先、季節の催しと記念の絵はがきが変わる。地区の追加は今回の対象外とする。鳩への危害、季節による施設停止、幸福度への罰則は設けない。

## 季節の暦

- 既存の1日120秒を維持する。各季節は15日、約30分。春の1日目から始まり、夏16日目、秋31日目、冬46日目、次の春61日目となる。1年は60日、約2時間。
- 季節は保存済みの `Time` から導出する。保存ファイルに別の季節カウンターを持たず、一時停止中は進まない。旧セーブは保存された時間に対応する季節へ自然に移行する。
- HUDには「春 · 3日目」のように季節と季節内の日数を表示する。境目には短い通知を出すが、プレイヤーの操作を遮らない。

## 景色

- 地面、街路樹、花壇の公園、空と日差しを季節色にする。春は若葉と花、夏は濃い緑、秋は紅葉、冬は落葉と淡い冬色。雪で歩道や鳩が見えにくくならないよう、冬の地面は薄い色調変化に留める。
- 建物の形、配置、当たり判定は変えない。季節の切替時と施設の建設・改良時にのみ施設モデルや地面の色を更新し、毎フレーム全モデルを作り直さない。既存のメッシュ統合と描画負荷への配慮を保つ。
- 朝昼夕のライティングは既存の連続変化を保ち、その上に季節の色調を軽く加える。鳩の羽色や選択表示の視認性を優先する。

## 鳩の行動

- 季節は行き先選択の加点にのみ影響する。春は公園と木、夏は噴水、秋は広場とパン屋、冬は木・住宅・日なたで休める公園に少し集まりやすい。性格と一日の生活リズムは引き続き優先され、どの季節にも食事、水浴び、散歩、交流、休憩、飛行を行える。
- 冬に噴水を止めたり、水浴びを危険な行動として扱ったりしない。寒さ・病気・負傷・死亡などの状態は追加しない。既存の鳩のお願いと通常の催しが、季節によって達成不能にならないことを条件とする。
- 季節の差は実際の行動頻度として見える強さにしつつ、個体差と乱数を残す。既存の行動 enum と表示名を可能な限り再利用する。

## 季節の催し

- 3日ごとの既存の「街の催し」はそのまま残す。別枠の「季節の催し」は、該当する季節中に自動で始まり、一度完成させる観察目標とする。通常の催しと並行して進み、ボタン連打ではなく、会場を整えた後の鳩や人の実際の行動で達成する。施設の「近く」は既存の `Near` と同じ、施設中心のマス座標でユークリッド距離2.1以内とする。
- 春「花見」：花壇の公園と街路樹を近くに置き、鳩が公園で羽繕いか日向ぼっこをする。
- 夏「水辺の集い」：噴水と花壇の公園を近くに置き、鳩が噴水で水浴びする。
- 秋「秋の市」：パン屋と広場を近くに置き、鳩がパン屋で食事し、人が買い物をする。
- 冬「冬の観察会」：街路樹と広場を近くに置き、鳩が木で休む。冬も穏やかに過ごす景色として表現する。
- 各観察は、その瞬間に会場の施設組合せが有効で、鳩または人が組合せの主施設を利用している場合だけ記録する。秋の食事と買い物はそれぞれ有効なパン屋で起きればよく、同じパン屋である必要はない。会場を移したり撤去したりしても、同じ季節内の記録済み観察は残り、会場を整え直せば続きを観察できる。
- 未完成のまま次季節に移ると、その年の途中経過はリセットする。罰則はなく、翌年の同じ季節に最初から再挑戦できる。完成済みの季節の催しも翌年に新しい絵はがきを作れる。進行中の季節、年、観察済み項目を保存し、ロード時にゲーム内時刻と合わない古い進行だけ破棄する。
- 絵はがきには季節、催し名、開催年・日、参加した鳩の名前を残す。名前は完成時のスナップショットとして保存する。季節ごとに異なる小さな絵柄を描く。通常の催しの絵はがきは変更しない。

## UIと保存

- 既存の「催し」タブに、今季の催しの会場条件・進行・残り日数と、通常の催しを明確に分けて表示する。両者の開催条件を混同させず、記念の絵はがきは同じタブで閲覧できる。限られたウィンドウ幅で文字切れや画面外へのはみ出しが起きないよう、既存の折返しとスクロールを使う。
- 季節の催しの進行状況と絵はがきは保存・再開できる。保存形式を拡張する際は `CurrentSaveVersion` を更新し、旧バージョンの保存を読み込めるよう既定値を補う。未知の将来版や壊れたデータの保護は既存の方針に従う。
- `README.md` と Unity 版 README に暦・行動・催しを反映する。ゲームの公開版番号や配布物の更新は別作業とする。

## 検証

- 暦の境目（15/16、30/31、45/46、60/61日目）、一時停止、保存と旧セーブからの復元を確認する。
- 季節ごとの目的地選択の傾向を固定乱数で検証し、基本行動と既存のお願い・催しが維持されることを確認する。
- 季節の催しは、会場不足、途中移設、実際の行動による達成、翌年の再挑戦、絵はがきの保存を検証する。
- Unity C# 検証、Mac ビルドを通し、季節ごとの画面と狭いウィンドウでの UI を目視確認する。描画負荷の既存ベンチマークも確認する。
