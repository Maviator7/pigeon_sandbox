# 下部ステータス欄の整理

## 問題

現在の下部欄は、選択中の建設操作、操作後のメッセージ、`town.Notice` を見出しなしで縦に並べる。実例では「時計台を建てる」「水辺の午後の絵はがきが届きました！」「まちの会計：収入47／維持費88.0」が同列に見える。収支は上部の予算欄にもあり、更新頻度や各行の役割が伝わらない。

## 表示

下部欄を、余白を保った左右2欄にする。左は「いまの操作」で、選択中の施設または観察モードと次にできる操作を示す。建設中は施設の効果を既存の `Tips` から表示する。右は「街のお知らせ」で、既存の `message` に入る操作結果・催しの案内と、`town.Notice` に入るお願い達成・新しい鳩などの出来事を示す。同じ文言は1回だけ表示する。`message` が施設の説明や操作ガイドであることは、UI側で代入時に付ける区分で判定し、右欄へは重複表示しない。案内は左の操作欄に置く。`town.Notice` が初期案内や建設失敗のヒントの場合は右欄で「ヒント」、鳩や街の出来事の場合は「できごと」と明示する。

`town.Notice` の「まちの会計：」で始まる定期収支だけを右欄から外す。金額は上部の予算欄にある。ほかの `town.Notice` は表示を維持する。操作結果と街のできごとが異なるときは、それぞれ短い小見出しを付けて右欄に並べる。通知の発生順や保存の内容は変更しない。

施設を選択した管理状態でも上段は左右2欄とし、左に「選択中の施設」と施設情報、右に街のお知らせを出す。改良・移設・撤去ボタンは下段で従来どおり全幅に配置し、処理も維持する。下部欄の高さは現行の192設計単位のままとし、上段の本文を各欄の矩形内のスクロール表示にする。長い説明や保存エラーも欄外やボタンに重ならず、スクロールして全文を読める。

上部の予算欄は既存の `Money`、`Income`、`Upkeep` をそのまま使う。予算の見出しに続けて「20秒ごと 収入 ¥…」「維持費 ¥…」の2行で周期を先頭に明示する。245設計単位の予算欄に収めるため、予算の見出しを含む3行は折り返さず、数値が大きいときは各行の文字サイズを可読な範囲で縮める。さらに大きい数値は単位を「万」に丸めて表示し、欄外に流さない。収支の計算、通知の発生、保存、操作イベントは変更しない。配色・フォントは現在の落ち着いた街づくりUIに合わせる。

## 確認

建設・観察・施設選択の3状態における見出し、通知の重複回避、管理ボタン、上部収支の表記を確認する。1280×800のMac画面で通常文と長文の収まりを見て、操作結果と街のできごとが混在しても読めることを確かめる。予算・収入・維持費に大きな値を入れた表示でも上部欄が重ならないことを確認する。C#検証、フォントサブセット確認、Macビルドを行う。
